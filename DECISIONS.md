# Architecture & trade-offs

- pnpm workspaces keep the React app, Express API, and shared contracts in one TypeScript repository. Strict shared Zod schemas and inferred types define health, authentication, account registration/verification/profile, discovery, catalogue, engagement, admin, archive, pagination, and error contracts at runtime and compile time.
- `app.ts` is the API composition root for global CORS/body parsing, feature-router mounting, and error boundaries. Health, authentication, account, discovery, catalogue, engagement, admin, and OpenAPI remain feature-oriented modules with narrow store interfaces; Prisma projections select only each response's required fields.
- PostgreSQL persistence uses four Prisma migrations, uniqueness constraints, 24-hour pending registrations, hashed browser bindings and single-use email-verification challenges, and explicit `archivedAt`/`removedAt` fields. Archive and remove operations preserve records and relationships. The deterministic idempotent seed creates 240 active books, 12 active genres, and two already-verified hashed-password user fixtures without network access; its genre reconciliation preserves an archived seed when an active librarian-created replacement owns the same name or slug.
- Public discovery returns exactly the available set up to six newest active books with a book-ID tie-breaker and preview-only fields. Reader catalogue queries are active-only, search title/author only, use stable sorts, and report archived detail as not found.
- Favourite genres are a full ordered replacement of zero to five unique active genres. Personalised results cap at six and follow preference, newest, and ID order while excluding the visible reading list. Reading-list upsert restores soft-removed state, and archived books remain as reader-safe unavailable history that can be removed but not updated.
- Librarian book and genre mutations use validated full inputs and transactional persistence. Books retain archived historical genre associations during edits and retain all associations when archived; restoration requires an active genre. Genre archive is blocked when it would leave an active book without another active genre, and active name/slug conflicts remain enforced across create, update, and restore.
- Authentication uses bounded scrypt password verification and a short-lived HS256 token in an HTTP-only, `SameSite=Lax` cookie. Public registration rejects privileged input and may stage Readers only. Candidate name/password hashes remain non-authenticated setup data until the same browser supplies the matching email, six-digit code, and hashed 256-bit pending-token binding; verification atomically commits the Reader credentials, consumes the challenge, clears the pending cookie, and creates the normal session. Duplicate or out-of-order requests cannot commit without that bound challenge. Codes expire after ten minutes, are single-use and five-attempt-limited, while pending setup expires after 24 hours. Resend has a 60-second cooldown including terminal outcomes, account endpoints use bounded process-local rate limits, and authenticated Reader/Librarian profile updates accept only the display name. Roles and verification state are reloaded from server-side users, not trusted from the JWT or client.
- Verification delivery is isolated behind an injected mail interface and the official Resend SDK. `RESEND_API_KEY` and `RESEND_FROM_EMAIL` must be configured together after sender/domain verification. If both are absent, valid register/resend requests fail uniformly before hashing, lookup, persistence, dispatch, or pending-cookie creation while login, profile, verification, and other application routes remain usable. With delivery configured, accepted existence outcomes use the same generic `202`; delivery runs best-effort in-process after the response, failed delivery immediately scrubs challenge secrets, and same-browser resend recovers after cooldown. Process exit can lose scheduled mail because there is no durable queue. Tests inject mocks and do not contact Resend.
- React Router separates the public landing/account-entry pages, protected reader pages, and librarian-only Back Room. The browser's non-authoritative pending-registration hint contains only normalized `{ email, startedAt }`; the HTTP-only pending cookie remains unreadable to the UI and missing/stale hints safely restart sign-up. A single authentication provider bootstraps the verified session; relative credentialed `/api` calls validate shared contracts and never expose JWT or pending-cookie values to JavaScript storage. Catalogue state lives in the URL, and shared components implement responsive, keyboard/focus, status, archive, and reduced-motion behavior across reader and admin flows. Visual genre truncation keeps a complete assistive-text list, while Fraunces Variable and IBM Plex Mono are bundled locally through Fontsource with swap behavior and no CDN dependency.
- OpenAPI 3.0.3 is generated from the Zod contracts with `@asteasolutions/zod-to-openapi` 7.3.4 and served through local `swagger-ui-express` 5.0.1. Its session and pending-verification cookie schemes describe the contract without publishing cookie values, credentials, verification codes/hashes, JWT secrets, or examples; 22 paths and 29 implemented operations are documented, including the four account paths and structured non-admin payload-too-large responses.
- API startup performs secret cleanup before listening and repeats it every five minutes, using a batch size of 100 and a maximum of 100 batches per run. Expired 24-hour setup is deleted only after challenge secrets are scrubbed; delivery failure also triggers immediate scrubbing. Generic logs avoid emitting account or secret data.
- Docker Compose is intentionally a trusted-local take-home environment: it exposes broad host ports, uses known privileged database credentials, root/dev-tool-heavy containers, Vite serving, and mutable base tags. Internet deployment is a non-goal and would require container/network hardening, a shared multi-instance rate-limit store and broader abuse controls, a durable verification-mail queue, production password cost, token revocation/key rotation, a reviewed explicit CSRF strategy, security headers, privileged-action audit logging, and structured observability. Password reset, email change, librarian onboarding, and a production email-delivery operational runbook remain out of scope.
- Automated tests use mocked Prisma stores for route and concurrency behavior rather than a database-backed concurrent integration suite. The final browser-backed QA service remained unavailable after retry, so rendered responsive geometry, complete physical-keyboard journeys, forced-colour/reduced-motion runtime behavior, console/network state, and rendered Swagger interaction remain manual checks. A registry-backed advisory scan also remains required because this environment's approval policy did not permit transmitting dependency metadata to the external registry.
